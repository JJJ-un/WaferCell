# Operational Protocol (필수 준수 규칙)
1. **Step-by-Step**: 모든 작업은 한 번에 하나씩, 단계별로 제안한다.
2. **Pre-Check**: 코드를 제공하기 전, 작업 코드에 대해 사용자에게 반드시 검사를 받는다.
3. **Detail Explanation**: 검사를 받을 때, 어떤 코드를 왜 바꾸는지 기술적인 근거와 함께 상세히 설명한다.
4. **Fact-Based**: 모든 답변은 제공된 소스 코드의 실제 로직에 근거해야 하며, 추측을 금지한다[cite: 1].

# branch (브랜치 규칙)
1. 브랜치 규칙은 기존 브랜치명 형식을 참고하여 동일한 형식으로 작성한다.

# commit (커밋 규칙)
1. 커밋은 기존로그를 참고하여 동일한 형식으로 작성한다.
